# Исправление отбора реальных задач

Распакуйте содержимое в текущую папку рядом с START.cmd с заменой файлов.
Затем используйте обычный START.cmd. Ключи, AB.toml, .bench и платный режим не меняются.
В начале поиска теперь видно `Discovery: test-aware-v2`.

Изменения:
- Вместо одного случайного порядка для всей выборки используются несколько диапазонов
  популярности в пределах прежнего общего repository_pool. Это не равномерная выборка
  всего GitHub и не классификация размера проекта.
- Наличие каталога tests/test/testing используется как приоритет поиска, не как доказательство.
- Список изменённых файлов PR проверяется до клонирования. PR без пары код/тест не тратит
  max_candidates на скачивание/сборку. API-бюджет продолжает учитывать каждый запрос.
- Кандидаты разных репозиториев получают очередь до повторных кандидатов одного проекта.
- discovery.json содержит счётчики, причины, этапы и короткие примеры, а не одну CAS-ссылку.
- Подробности прежних запусков можно получить через EXPORT_DISCOVERY.cmd без сети и модели.

Не изменены: квалификация FAIL_TO_PASS/PASS_TO_PASS, запрет подмены задачи фикстурой,
история/хронология issue, разделение A/B, ADCP, DSH, независимая приёмка, числовые бюджеты.
Наличие тестового файла не гарантирует пригодную задачу; сборка и тесты всё ещё могут отказать.
Исчерпание ограниченной выборки остаётся возможным и теперь диагностируется явно.

Из приложенных оператором файлов установлены 39 записей отклонений и 0 пригодных задач.
Только одна конкретная пара request/response объяснена как NO_CODE_AND_TEST_CHANGE.
Причины остальных отклонений отсутствовали; это исправление не выдаёт их за известные.
